# 曲のメタデータ（metadata.yaml）

曲ごとに `scores/<slug>/metadata.yaml` を1つ用意し、`scripts/build_score.py --metadata` で読み込みます。
新しい曲では [templates/metadata.yaml](../templates/metadata.yaml) をコピーしてください。

- トップレベルで使えるのは、この文書に載っているフィールド（末尾の「旧フィールド」を含む）だけです。それ以外のフィールドはエラーになります（フィールド名の打ち間違いが黙って無視されるのを防ぐためです）。
- すべてのフィールドは省略できます。省略すると「既定値」列の値が使われます。
- `midi`、`quantize`、`notation`、`dynamics`、`credits` の中でも、以下に載っているサブフィールドだけが使えます。打ち間違いは同様にエラーになります。

## クレジットと文字

これらのフィールドはタイトル部、続きページのヘッダー、MusicXML のクレジットにだけ影響し、採譜には影響しません。値はそのまま出力されます（日本語で書けます）。PDF では漢字・かなとラテン文字の間にスペースを自動で入れないため、書いたスペースはそのまま印字されます（例外：全角句読点・括弧類の直後、およびかな・漢字と全角括弧の間の半角スペースは、日本語の組版規則に従って印字されません）。行われる処理は、前後の空白（全角スペースを含む）の除去と、改行・タブなど連続する ASCII の空白を半角スペース1つにまとめることだけです。
文字をコピーするとき、漢字・かなとラテン文字の間に書いた半角スペースは pdftotext でも pdf.js でも保持されます。全角スペース（U+3000）は正しく印字されますが、pdftotext と pdf.js ではコピーすると半角スペースになり、PyMuPDF では U+3000 のまま残ります（逆に PyMuPDF は、漢字・かなの隣の半角スペースを落とします）。
MusicXML には、メタデータの元の値が上記の空白処理なしで書き込まれます。

| フィールド | 型 | 既定値 | 用途 | 例 |
| --- | --- | --- | --- | --- |
| `title` | 文字列 | `Untitled` | 曲名：PDF のタイトル、続きページのヘッダー、PDF 文書のタイトル、MusicXML の `work-title` と `movement-title` | `命に嫌われている。` |
| `subtitle` | 文字列 | なし | 曲名の下の1行。MusicXML の `work-number`（MuseScore 3 ではサブタイトルとして表示）とサブタイトルのクレジット | `Self-cover ver.` |
| `artist` | 文字列 | なし | アーティスト：タイトル部と続きページのヘッダー。`subtitle` がないときは MusicXML のサブタイトルのクレジットになる | `カンザキイオリ` |
| `album` | 文字列 | なし | アルバム：アーティストの後ろに `『…』` として印字 | `不器用な男` |
| `lyricist` | 文字列 | なし | 作詞（ラベル `作詞`） | `カンザキイオリ` |
| `composer` | 文字列 | なし | 作曲（ラベル `作曲`） | `カンザキイオリ` |
| `vocal` | 文字列 | なし | 歌（ラベル `歌`） | `カンザキイオリ（セルフカバー）` |
| `transcriber` | 文字列 | なし | ドラム譜の採譜（ラベル `ドラム採譜`）。MusicXML では `arranger` 種別のクレジット | `音宮` |
| `arranger` | 文字列 | なし | ドラム編曲（ラベル `ドラム編曲`） | `音宮` |
| `note` | 文字列 | なし | 備考（ラベル `備考`）。たとえば採譜者による再創作を含むことの説明に使う | `本譜には採譜者による再構成・創作を含みます。` |
| `copyright` | 文字列 | なし | 1ページ目の下部に印字。MusicXML の `rights` | `© 2026 …` |
| `credits` | マッピング | なし | 役割ラベルの書き換え（後述） | `{arranger: アレンジ}` |
| `legend` | 真偽値 | `false` | 1ページ目に凡例を印字するか。YAML の真偽値で書く必要があり、引用符付きの文字列（`"false"` など）はエラーになる | `false` |
| `slug` | 文字列 | なし | 記録用のみ（ディレクトリ名と同じ）。プログラムは使わない | `inochi-ni-kirawareteiru` |

MusicXML では次のように書き出されます。`title` は `work-title` と `movement-title`、`subtitle` は `<work>` 内の `work-number`、
`composer`・`lyricist`・`arranger` は `creator`、`artist`・`album`・`vocal`・`transcriber`・`note` は同名の
`miscellaneous-field` です。1ページ目の `credit` は、曲名が中央、サブタイトル（`subtitle`、なければ `artist`）が中央、`composer` が右寄せ、
`lyricist` が左寄せ、`transcriber`（credit の種別は `arranger`）が左寄せです。`credit` を読むソフトウェアはこれらのクレジットを表示します。
MuseScore 3 は `credit` を読みません。開くと、曲名（`movement-title` から）、サブタイトル（`work-number` から。つまり `subtitle` を書いた場合のみ）、作曲、作詞が表示され、`artist` と `transcriber` は表示されません。
PDF の文書プロパティは、タイトルが `<title> ドラム譜`、作成者が `transcriber` と `arranger`
（同じ場合は1回だけ）、サブジェクトが `artist / album` です。

### タイトル部の組み立て方

1ページ目のタイトル部は、上から順に次のとおりです。

1. `title`（大きな太字）
2. `subtitle`
3. `artist　『album』`
4. 楽曲のクレジット：`lyricist`、`composer`、`vocal` の順
5. ドラム譜のクレジット：`transcriber`、`arranger` の順
6. `備考：note`
7. `BPM <テンポ>`
8. 凡例（`legend: true` またはコマンドラインの `--legend` のときだけ印字）

4行目と5行目では、**値がまったく同じ**（前後の空白を除いたうえで1文字ずつ比較）役割を1つのラベルにまとめ、`・` でつなぎます。人が異なる場合は全角スペースで区切ります。
比較では内部の連続した空白はまとめません。`A  B`（スペース2つ）は `A B` と同じ見た目で印字されますが、同じ値とは扱われません。

| メタデータ | 印字される行 |
| --- | --- |
| `lyricist: A`、`composer: A`、`vocal: B` | `作詞・作曲：A　歌：B` |
| `lyricist: A`、`composer: B` | `作詞：A　作曲：B` |
| `transcriber: C`、`arranger: C` | `ドラム採譜・編曲：C` |
| `transcriber: C`、`arranger: D` | `ドラム採譜：C　ドラム編曲：D` |

まとめるとき、最初のラベルが `ドラム` で始まっていれば、後ろのラベルの先頭の重複する `ドラム` は省かれるため、`ドラム採譜・ドラム編曲` ではなく `ドラム採譜・編曲` になります。人名の書き方が少しでも違えば（たとえば一方に「（セルフカバー）」が付いていて他方にない場合）、まとめられません。

### credits：ラベルの書き換え

`credits` のキーは役割名、値は印字するラベルです。書き換えられる役割は `lyricist`、`composer`、`vocal`、`transcriber`、`arranger`、`note` です。
`artist` と `album` も書けますが、タイトル部ではこの2つにラベルを印字しないため効果はありません。それ以外のキーはエラーになります。

```yaml
credits:
  vocal: ボーカル        # 「歌：…」が「ボーカル：…」になる
  arranger: アレンジ     # 「ドラム編曲：…」が「アレンジ：…」になる
```

## ドラムマップとトラック選択

| フィールド | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `drum_map` | 文字列 | `gm` | 組み込みマップ名（`gm`、`fpc-default`）またはマップ YAML のパス。相対パスはまずメタデータファイルのあるディレクトリからの相対で探し、見つからなければカレントディレクトリからの相対で探す。コマンドラインの `--drum-map` が優先 |
| `note_map` | マッピング | なし | `drum_map` の上で音符を1つずつ書き換える：`MIDI ノート番号: 楽器`。書き方は [drum-maps.md](drum-maps.md) を参照 |
| `midi.tracks` | リストまたは単一の値 | 自動 | これらのトラックだけを使う。文字列はトラック名にその文字を含むもの（大文字小文字を区別しない）、整数はトラック番号（0 始まり。0 番トラックは通常テンポトラック）。コマンドラインの `--track`（名前のみ）が優先 |
| `midi.channels` | リストまたは単一の整数 | 自動 | これらの MIDI チャンネルだけを使う。1–16 で指定（GM のドラムは 10、FPC の直接エクスポートは 1）。コマンドラインの `--channel` が優先 |

`tracks` と `channels` を同時に指定した場合は、両方の条件を満たすものだけを使います。どちらも指定しない場合は自動で選びます。ファイルに音符を含むトラック／チャンネルが1つだけならそれを使い、
そうでなければチャンネル 10 をすべて使い、それもなければトラック名に `fpc`、`drum`、`perc`、`kit`、`ドラム`、`鼓` を含むトラックを使います。それでも判断できなければ、エラーにして各トラックを一覧表示します。

```yaml
drum_map: fpc-default
note_map:
  40: hand-clap          # この FPC キットではハンドクラップが 40 番パッドにある
midi:
  tracks: [FPC]          # または [1]（番号指定）、あるいは channels: [10]
```

## クオンタイズ

| フィールド | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `quantize.subdivision` | 整数 | `4` | ストレートのグリッド：`4`＝16分音符、`2`＝8分音符。この2つの値のみ指定できる |
| `quantize.tuplets` | 文字列 | `auto` | `auto`：拍ごと・声部ごとに3連符として記譜するか判断する。`off`：3連符を記譜しない（3連符があるとエラー）。引用符なしの `off` は YAML では false と読まれるが、同じく `off` として扱う |
| `quantize.flam_window` | 数 | `1/8` | 装飾音のウィンドウ（四分音符単位。`1/8` は32分音符）。`1/16`、`0.125` なども書ける。`0` にすると装飾音の判定を無効にする |

判定規則（各拍の手の声部・足の声部について、それぞれ別に決めます）：

- この拍のこの声部の音がすべてストレートのグリッドから 1/24 拍以内：ストレートで記譜します。
- そうでなく、`tuplets: auto` で、すべての音が3連符のグリッドから 1/32 拍以内：3連符として記譜します
  （`subdivision: 4` のときグリッドは 1/6 拍で、3連符と16分の6連符を記譜できます。`subdivision: 2` のときグリッドは 1/3 拍です）。
  わずかな人為的なずれ（約 ±0.015–0.025 拍）は通常認識されます。1/32 拍を超えてずれた3連符はエラーになるので、先に DAW でクオンタイズしてください。
- 例外：ある音が、3連符の位置ではない64分音符の位置（たとえばちょうど 3/16 拍）から 1/192 拍以内にあるとき、
  3連符としては記譜せず、32分／64分音符のリズムであることを示すエラーにします。人為的なずれでちょうどそのような位置の近くに音が寄った場合も同じエラーになります
  （たとえば 1/3 拍の位置の音が約 0.02 拍早く、5/16 拍付近に来た場合）。
- `subdivision: 4` のとき、8分音符と8分3連符が同じ拍にある場合（拍頭、1/3、1/2 拍の位置）は、ちょうど6連符のグリッドに乗るので6連符として記譜します。
  16分音符と3連符が同じ拍にある場合（1/4 と 1/3 拍の位置など）は、どちらのグリッドにも合わないのでエラーです。
- どれにも当てはまらない場合：楽譜の先頭から数えて何拍目のどの声部かを示してエラーにします。「だいたい合う」グリッドに無理に当てはめることはしません。
- 3連符として記譜される拍で、すべての音がストレートの16分の位置にある声部（たとえばもう一方の声部が踏む4分音符や16分音符）は、3連符の記号を付けず、通常どおりストレートで記譜します。
- フラムの主音は本来遅れるものなので、許容範囲を 1/16 拍に広げます（上記の64分音符位置の例外も適用されません）。装飾音がグリッドに乗っているときは、装飾音の位置から主音を特定することもできます。

装飾音と重複トリガー（同じ MIDI ノート）：

- 最初の打鍵との差が 1/48 拍以内の打鍵は同じ打鍵（重複トリガー）と見なし、ベロシティが最大のものを残します。その個数は注意で知らされます。
- ある打鍵の前 `flam_window` 以内にある、より弱い打鍵は、その装飾音として記譜します。1つの主音に付けられる装飾音は最大2つで、1つならフラム（斜線付きの小さな8分音符）、2つならドラッグ（連桁でつないだ小さな16分音符2つ）です。
  連続してクレッシェンドする速い打鍵は装飾音とは見なさず、32分音符としてエラーになります。
- それ以外で、2つの打鍵が同じ位置にクオンタイズされる場合はエラーです。どちらかを黙って落とすことはしません。
- 異なる音符の間では装飾音の判定を行いません。

## 拍子記号・テンポ・弱起

| フィールド | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `time_signature` | 文字列 `"n/4"` | なし | MIDI に拍子記号イベントがないときに使う。MIDI にあるときは MIDI の最初の拍子記号と同じでなければならず、違えばエラー。それ以降の拍子記号の変化は常に MIDI から取る。どちらにもなければ 4/4 とし、注意を出す。1/4–12/4 のみ対応 |
| `tempo_bpm` | 数 | 楽譜の開始位置（先頭の余分な拍を除いた後）で有効な MIDI のテンポ。開始位置より前にテンポイベントがなければ最初のもの、MIDI にテンポイベントがなければ 120 | タイトル部の `BPM` と、MusicXML の第1小節のテンポ。範囲は 10–400。MIDI と異なる場合は注意を出し、譜面ではメタデータの値を使う。MIDI 内のその後のテンポ変化は引き続き印字される |
| `pickup_beats` | 整数 | `0` | 弱起小節の拍数（四分音符）。弱起小節の番号は 0 で、自分の拍子記号（`2/4` など）を印字し、音符を含められる |
| `source_leading_beats` | 整数 | `pickup_beats` と同じ | 元の MIDI で第1小節（弱起の後の最初の完全な小節）が始まる位置を、拍（四分音符）で指定する。`0 ≤ pickup_beats ≤ source_leading_beats` が必要 |

譜面は元の MIDI の `source_leading_beats − pickup_beats` 拍目から始まります（それより前は捨てられます）。捨てられる部分に音符があるとエラーになります。例：元の MIDI の冒頭に丸1小節（4拍）の
空白があり、譜面にはそのうち2拍だけを残して2/4の弱起として印字したい場合は、`source_leading_beats: 4`、`pickup_beats: 2` と書きます。
弱起小節より後の小節線は MIDI の拍子記号に従って決まります。MIDI の拍子記号の変化はこれらの小節線の位置にちょうど一致していなければならず、そうでなければエラーになります。

## 強弱

| フィールド | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `dynamics.ghost_below` | 整数 | なし（無効） | 手のベロシティがこの値**未満**の音をゴーストノートとして記譜する：PDF では符頭に括弧が付き、MusicXML では `notehead parentheses="yes"` になる |
| `dynamics.accent_above` | 整数 | なし（無効） | 手のベロシティがこの値**を超える**音にアクセント記号 `>` を付ける（MusicXML の `accent`） |

足（バスドラム、ハイハット（ペダル））にはゴーストノートやアクセントの記号は付きません。

## 記譜

| フィールド | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `notation.repeats` | 文字列 | `simile` | 反復記号の記譜モード。`simile`：1小節（`%`）および2小節（`//`）の反復記号を使う（既定）。`full`：`%`・`//` に加え、フレーズ区切りの反復記号（`|: ... :|`）および1番・2番括弧（`1.`／`2.`）で隣接する反復フレーズを折りたたむ。`off`：反復記号を使わず空でない小節をすべてそのまま記譜する。引用符なしの `off` は YAML では false と読まれるが、同じく `off` として扱う。コマンドラインの `--repeats` が優先 |
| `notation.repeat_counters` | 真偽値 | `false` | 1小節の `%` が2小節以上連続するとき（同じ小節が3小節以上続くとき）、各 `%` の上に反復回数（`2`、`3`、`4`、…）を印字するか。既定（`false`）では印字せず、`true` を指定したときだけ印字する。YAML の真偽値で書く必要があり、引用符付きの文字列（`"true"` など）はエラーになる |
| `notation.beam_eighths` | 文字列 | `beat` | 8分音符の連桁のまとめ方。`beat`：拍ごとにまとめ、拍をまたがない（既定）。`half-bar`：4/4 の非弱起小節において、前半（第1–2拍）または後半（第3–4拍）が通常のストレートな8分音符4つだけで連続する場合、その4つを1本の連桁でまとめる（手・足の声部ごとに独立して判定）。コマンドラインの `--beam-eighths` が優先 |
| `notation.system_spacing` | 数 | `1.1` | PDF の段間（システム間の縦間隔）の倍率（`0.7`–`2.5`）。`1.0` が MusiXTeX 標準の詰めた間隔、`1.0` 未満でより狭く、`1.0` 超でより広くなる。PDF のレイアウトのみに影響し、MusicXML には影響しない。コマンドラインの `--system-spacing` が優先 |

既定では `%` の上に `2`、`3`、`4`、… の反復回数は印字されません。`notation.repeat_counters: true` を設定した場合のみ、2小節以上連続する `%` の上に回数が印字されます（単独の `%`、つまり同じ小節が2小節だけ続く場合には回数を印字しません）。2小節反復の `//` は記号自体に必ず `2` を伴い、`repeat_counters` の対象外です。反復記号の成立条件や改ページ時の扱い、および連桁の規則は [notation-conventions.md](notation-conventions.md) の「反復記号」「連桁」を参照してください。

```yaml
notation:
  repeats: simile         # simile（既定）、full、または off（--repeats が優先）
  repeat_counters: false  # 既定は false。true にすると連続する % の上に回数（2, 3, 4…）を印字
  beam_eighths: beat      # beat（既定）または half-bar（--beam-eighths が優先）
  system_spacing: 1.1     # PDF の段間倍率（0.7–2.5、既定 1.1、1.0 で標準の詰めた間隔。--system-spacing が優先）
```

| フィールド | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `sections` | マッピング | なし | トップレベルで指定する「小節番号: リハーサルマーク」の対応表。キーは1以上の整数で、曲の小節番号の範囲内（弱起の0小節目は指定不可。`notation.repeats` の設定に関わらず、常に折りたたみ前の元の小節番号で指定する）。値は前後の空白を除いて1–24文字の印字可能な ASCII 文字列のみ（日本語などの非 ASCII 文字や空文字列はエラー） |

各セクションの先頭小節には、直前に複縦線（曲の先頭、弱起小節の直後、または反復小節線 `|:`／`:|` と重なる位置を除く）と小節上部の枠付きリハーサルマークが印字されます。また、セクションの開始位置では複数小節休符が分割され、1小節（`%`）・2小節（`//`）の反復記号がリセットされ、改行の最適化でもセクション先頭からの改段が優先されます。詳細は [notation-conventions.md](notation-conventions.md) の「セクションとリハーサルマーク」を参照してください。

```yaml
sections:
  1: Intro
  9: A
  25: Chorus
```

## 旧フィールド

初期のメタデータにあったフィールドも引き続き読み込めますが、新しいファイルでは新しい書き方を使ってください。

| 旧フィールド | 新しい書き方 | 説明 |
| --- | --- | --- |
| `beats`、`beat_type` | `time_signature: "4/4"` | どちらか一方だけを書いた場合は、もう一方を 4 として扱う。`time_signature` もあるときはそちらが優先 |
| `quantize_divisions_per_beat` | `quantize.subdivision` | 両方あるときは `quantize.subdivision` が優先 |
